# 每日开发记录规范

本目录是 HomeAgent-ROS2 的**按日期开发事实记录**。从 2026-10-07 起，每个实际开发日必须维护一个 `YYYY-MM-DD.md`。

## 必须记录的内容

每天的记录至少包含：

1. **当天目标**：今天要解决什么。
2. **环境与基线**：设备、分支、关键依赖、起始 commit。
3. **工作过程**：实际做了哪些修改，按时间/阶段排序。
4. **验证方法**：执行了什么 build / test / demo / benchmark。
5. **结果数据**：成功/失败、测试数量、关键输出、性能或功能结果。
6. **问题与修复**：症状、定位过程、根因、修复方案、修复后的验证结果。
7. **代码提交**：commit SHA + message。
8. **未完成项**：明确哪些还没有验证，不把“已实现”和“已验证”混为一谈。
9. **下一步**：下一次从哪里继续。

## 记录原则

- 只写实际发生的事情，不补造结果。
- “代码已写”“构建通过”“端到端通过”“真机/仿真通过”必须明确区分。
- 遇到问题必须保留，不删除失败记录；修复后在同一问题条目下补充修复结果。
- 重要命令、错误码、测试数量和 commit SHA 尽量保留。
- API Key、密码、Token 等敏感信息严禁写入日志。
- 当天有多个阶段时，仍记录在同一个日期文件中，用 Phase/时间段分节。
- `docs/DEVELOPMENT_LOG.md` 只做总索引和高层摘要；详细事实以本目录为准。
