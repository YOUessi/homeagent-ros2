## 9. Phase 0.6：可信世界状态边界

识别到一个架构风险：

> 即使 LLM 不能直接控制机器人，如果允许 LLM 自己提供 `recipient_age`、`object_tags`、`forbidden_zones`，它仍然可以“伪造安全上下文”绕过规则。

因此新增 `homeagent_context`。

新链路：

```text
Agent
  ↓
ActionCandidate      ← 不可信
  ↓
Trusted Context Resolver
  ├── household memory
  └── policy
  ↓
ActionProposal       ← 带可信上下文
  ↓
Safety Engine
  ↓
Approved action
```

安全上下文只允许来自：

- Household Memory。
- 固定政策参数。
- 后续可信感知/身份系统。

LLM 返回的 context 主动丢弃。

manipulation：

```text
pick / place / handover
```

如果目标对象不存在可信 Memory：

```text
UNTRUSTED_SAFETY_CONTEXT
```

默认拒绝。

### V-007 已知对象

先向 Memory 写入已知 `cup`：

```text
pick(cup)
→ Context trusted=True
→ Safety ALLOW
→ MOCK_SKILL_COMPLETE
```

### V-008 未知对象

```text
pick(unknown_item)
→ Context trusted=False
→ Safety REJECT
→ UNTRUSTED_SAFETY_CONTEXT
```

### V-009 禁区

Policy 中：

```text
forbidden_zones = [utility_room]
```

执行：

```text
navigate(utility_room)
→ Trusted Context 注入禁区
→ Safety REJECT
→ FORBIDDEN_ZONE
```

并在观察窗口内确认没有 SkillResult。

## P-005 LLM 可以伪造安全上下文

- 状态：架构级解决。
- 风险：
  如果 LLM 输出：
  ```json
  {
    "recipient_age": 20,
    "object_tags": []
  }
  ```
  Safety Engine 无法判断这些信息是否真实。
- 根因：
  Agent proposal 与可信 world state 没有 trust boundary。
- 修复：
  新增 `homeagent_context`：
  ```text
  ActionCandidate
  → Trusted Context Resolver
  → ActionProposal
  → Safety
  ```
- 验证：
  - LLM/parser context 被丢弃。
  - unknown object -> untrusted -> reject。
  - forbidden zone 由可信策略注入。
- 结论：
  LLM 不拥有安全事实的定义权。


  4. 设置 remote：

  5. 将 Tang 本地 main 的完整历史 push 到 GitHub。
- 权限核验：
  `gh auth status` 显示 token scopes：
  ```text
  gist
  read:org
  repo
  ```

- 结论：

- 决策：不污染宿主安装。`scripts/build_and_test.sh` 在宿主显式 `--packages-skip homeagent_gazebo_plugins`；Gazebo plugin 由 Docker smoke/demo 全量构建和验证。
- 验收口径：宿主 10 个非 Gazebo-plugin package + 31 个逻辑测试；Docker 11 个 package 全量构建 + Gazebo runtime 验证。
